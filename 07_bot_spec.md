# 07. Telegram Bot Spec

Пользовательское подключение Telegram, настройки и доставка уведомлений доступны только с активной подпиской RaceSide Plus. После окончания подписки доставка приостанавливается, а настройки сохраняются. Общая модель доступа определена в `18_subscription_concept.md`. Технический support-бот от пользовательской подписки не зависит.

## Роль

Пожелания со страницы `/feedback` поступают техническому support-боту через `support.dispatch_feedback`, независимо от подписки посетителя. Используются существующие `TELEGRAM_SUPPORT_BOT_TOKEN` и `TELEGRAM_SUPPORT_CHAT_ID` или `TELEGRAM_SUPPORT_USERNAME`. Сообщения хранятся в админке до и после доставки; worker повторяет отправку после временного сбоя.

Telegram-бот RaceSide пишет только тогда, когда пользователю действительно нужно внимание:
- напоминает о выбранных сессиях;
- сообщает, что результаты готовы;
- напоминает о незаполненном прогнозе;
- присылает выбранные новости с изображением и ссылкой на материал.

Уведомления о погоде, чемпионате, лигах, опросах и дневных дайджестах не входят в текущую Telegram-интеграцию.

## Настройки

### Новости

- `Все новости` — каждый новый материал после успешной AI-обработки;
- `Любимые пилоты` — новости с тегами избранных пилотов;
- `Любимая команда` — новости с тегами избранной команды.

Новость отправляется с изображением, русским заголовком, короткой сводкой, источником и кнопкой `Читать подробнее`. Если Telegram не может загрузить изображение, worker отправляет то же сообщение без него.

### Фентази

Единственная настройка — `Дедлайн по прогнозам`.

Для квалификационной и гоночной части отдельно:
- за 4 часа до дедлайна;
- за 15 минут до дедлайна;
- только если соответствующая часть прогноза ещё не заполнена.

Поул относится только к квалификационной части. Топ-10 и специальные прогнозы относятся к гоночной части.

### Сессии

Настройки задаются отдельно для:
- практик;
- спринт-квалификации;
- квалификации;
- спринта;
- гонки.

Для каждой группы доступны:
- включение или отключение уведомлений;
- напоминания за 24 часа, 1 час и 15 минут;
- режим `Без спойлеров`.

Если режим без спойлеров включён, сообщение после финиша сообщает только о готовности результатов и ведёт на сайт. Если режим выключен, сообщение показывает топ-3.

Изменение времени или отмена сессии отправляется только пользователям, у которых включена соответствующая группа сессий.

## Команды

- `/start` — подключение по одноразовой ссылке или приветствие;
- `/help` — доступные команды;
- `/next` — ближайшая сессия во времени пользователя;
- `/summary` — последняя дневная сводка по запросу пользователя;
- `/settings` — ссылка на настройки в RaceSide;
- `/unsubscribe` — отключение уведомлений.

Команда `/summary` остаётся ручной и не создаёт автоматический дайджест.

## Отправка

```text
Telegram подключён
→ категория включена
→ событие подходит под индивидуальные настройки
→ уведомление ещё не отправлялось
→ durable queue
→ Telegram API
→ журнал результата
```

- Все отправки идут через `notification_queue`.
- `dedupe_key` не позволяет повторить одно событие одному пользователю.
- Каждая запись отправляется независимо: ошибка одного сообщения не блокирует следующие.
- Временная ошибка повторяется с задержкой; после трёх попыток запись становится `failed`.
- Если пользователь заблокировал бота, `telegram_accounts.is_active` переключается в `false`.
- Сообщения отправляются сразу, без тихих часов и автоматических дайджестов.
- Текст использует Telegram HTML, эмодзи и inline-кнопки; данные из источников экранируются.
- Raw link token не хранится и не логируется.
- Telegram webhook принимает запросы только с настроенным secret token.

## Команды worker

```text
node worker/index.mjs notifications.enqueue
node worker/index.mjs notifications.dispatch
```

`notifications.enqueue` запускается раз в 5 минут после синхронизации календаря, результатов, новостей и фентази. Сразу после сборки worker вызывает `notifications.dispatch`; отдельный минутный polling не используется.

Для режима `Все новости` действует защитный лимит: не более 30 новостных уведомлений пользователю за скользящие 24 часа. Уведомления по избранным пилотам и команде не расходуют этот лимит, если режим `Все новости` отключён.

## Support-бот

Технические уведомления отправляются отдельным ботом и не смешиваются с
пользовательским каналом уведомлений. Для него используются
`TELEGRAM_SUPPORT_BOT_TOKEN` и либо `TELEGRAM_SUPPORT_CHAT_ID`, либо
`TELEGRAM_SUPPORT_USERNAME`. Если указан username, администратор сначала пишет
боту `/start`, после чего chat ID определяется по входящему личному сообщению и
не показывается в интерфейсе. В production `TELEGRAM_SUPPORT_CHAT_ID` должен
быть сохранён явно: Telegram хранит входящие обновления ограниченное время, и
поиск только через `/start` не переживает длительный перерыв или перезапуск.
Внутренние worker-задачи дополнительно могут восстановить адресат по активной
подтверждённой Telegram-связи с тем же username, не записывая chat ID в логи.

Задача `support.send_daily_report` запускается ежедневно в `07:00 UTC`
(`10:00 Europe/Moscow`). Она присылает итоги предыдущего московского дня:
фоновые задачи, публикации, доставку Telegram, расходы AI API и X API,
сообщения читателей и активные находки. Отдельным блоком указывается текущее
состояние сайта, worker, планировщика и источников.

Команда worker:

```text
node worker/index.mjs support.send_daily_report
```
