Уточнение от 3 октября 2026: в режиме «Сессии» сверху остаётся только Гран-при. Далее выбирается общий пилот и две сессии в одинаковых блоках, каждый со своим кругом. ## 2. Границы первой версии и допущения

### Обязательная V1 с подпиской

- Раздел `/telemetry` внутри RaceSide с серверной проверкой подписки.
- Пользователь с активной подпиской получает полный Telemetry Hub.
- Пользователь без подписки после входа получает одно заранее подготовленное демо-сравнение для Гран-при, который прошёл два завершённых этапа назад.
- Гость не получает телеметрические данные и видит действие `Войти и посмотреть демо`.
- Выбор сезона, Гран-при, сессии, пилотов и кругов.
- Все пять режимов: Lap Compare, Best Lap Compare, Session Compare, Teammate Compare, Track Evolution.
- Delta, speed, throttle, brake, gear, RPM, DRS; отсутствие отдельного канала корректно обрабатывается.
- Общая дистанционная ось, синхронный курсор, zoom/pan, интерактивная карта, выбор поворота и карта преимущества.
- Метрики RaceSide, анализ поворотов и фактические rule-based Insights.
- Постоянные ссылки, OpenGraph и серверные share-карточки во всех форматах ТЗ.
- Полноценные desktop/mobile сценарии, обработка ошибок, SEO, события аналитики и контролируемый запуск.

Этапы 0–5 дают внутреннюю версию основного сравнения. Это промежуточная контрольная точка, а не полное выполнение Definition of Done из раздела 84 ТЗ. Первая публичная версия требует завершения этапов 0–11.

### Отложено в соответствии с ТЗ

- Три и четыре одновременные телеметрические линии: поддержать расширяемый контракт, первоначальный UI оптимизировать под две.
- Live-телеметрия в новом Hub: предусмотреть совместимость, интеграцию realtime оставить отдельной задачей. Существующий LIVE продолжает работать.
- Средний темп stint, деградация шин и сравнение stint; сохранение избранного в аккаунте; AI narrative.
- Year-to-year comparison исключён, а не включён в ближайший backlog.

### Принятые допущения

1. Основной путь — `/telemetry`, название раздела — RaceSide Telemetry. Пользовательские тексты остаются русскими; английские названия режимов в плане служат привязкой к ТЗ.
2. Сезоны доступны только при подтверждённом покрытии телеметрией. Наличие спортивного архива 2020–2026 не доказывает наличие телеметрии за все эти годы.
3. Session Compare сравнивает две сессии одного пилота в одном уикенде. Track Evolution может показывать ряд из нескольких сессий, сохраняя две линии в подробном сравнении.
4. Источник V1 — OpenF1 по прямому решению пользователя. Этап 0 проверяет его покрытие, качество и условия использования, а не выбирает другой источник. FastF1 и fallback на сторонний provider не входят в реализацию V1; отсутствие данных OpenF1 обрабатывается явно.
5. Сроки и стоимость сейчас не фиксируются: сначала нужны проверка источников и измерение обработки реальных сессий. Точность и размер покрытия — существенные зависимости плана.
6. Список «популярных сравнений» строится по реальным агрегированным событиям. До накопления статистики показываются последние сессии и предложенные сравнения без выдуманных показателей популярности.
7. Правила доступа, стоимость и рекламная модель определены в `18_subscription_concept.md` и имеют приоритет над прежним требованием публичной телеметрии без регистрации.

Предусмотреть точку расширения provider fallback из ТЗ, но не подключать второй источник в V1. Не подмешивать данные стороннего provider для заполнения пропусков.

- [ ] Хранить negative cache для временно недоступных данных с ограниченным сроком; не превращать разовый сбой в постоянное отсутствие телеметрии.

**Артефакты:** OpenF1Provider, worker jobs, кеш, диагностика загрузки и тесты провайдерного контракта.

**Готово, когда:** одна сессия полностью проходит загрузку; повторная подготовка идемпотентна; конкурентные запросы не создают дубли; при отключении OpenF1 сохранённая история открывается, а отсутствующие данные дают корректное состояние недоступности и возможность повторить запрос.

## 8. Этап 3 — нормализация по дистанции и delta

**Цель:** получить корректную общую ось для сравнения разных кругов.

Pipeline: raw → cleaning → lap boundaries → distance → normalization → interpolation → delta → cached normalized dataset. Сегментация поворотов и производные метрики подключаются на этапах 6–7.

Задачи:

- [ ] Удалить дубликаты, некорректные timestamps и физически невозможные значения; отмечать выбросы, шум и gaps, сохраняя исходные данные для диагностики.
- [ ] Определить границы круга, elapsed time от линии старта и закрытие трассы; не допускать скачков через старт/финиш и немонотонной дистанции.
- [ ] Установить приоритет расчёта distance: проверенная дистанция источника либо восстановление по скорости/времени с привязкой к геометрии. Выбранный метод и его погрешность записывать в dataset.
- [ ] Различать пройденную машиной дистанцию и canonical progress трассы. Разные траектории пилотов не должны ошибочно сопоставляться как одинаковая физическая точка только по проценту собственного пути.
- [ ] Интерполировать на общую distance grid; шаг около 5 м — стартовый параметр для проверки, а не обещанная точность исходного измерения.
- [ ] Непрерывные каналы обрабатывать выбранной интерполяцией; gear, boolean brake и DRS — дискретно. Не создавать несуществующие передачи и промежуточные состояния.
- [ ] Не интерполировать через большие разрывы и не экстраполировать недостающий старт/финиш без обоснования. Неполный круг может быть доступен для просмотра, но не давать достоверную full-lap delta.
- [ ] Рассчитать `delta(d) = elapsedA(d) − elapsedB(d)`: отрицательная delta означает, что A быстрее B. Для нескольких traces считать относительно явно выбранной опорной линии.
- [ ] Сверять финишную delta с разностью времён кругов и промежуточную с секторами. Не растягивать искусственно кривую, чтобы скрыть расхождение.
- [ ] Разделить точность расчёта и детализацию отображения: аналитика считается до downsampling; формат для графика готовится отдельно.
- [ ] Зафиксировать численные допуски на контрольных datasets, точность вывода и минимальное качество для публикации метрик.

**Обязательные проверки:** одинаковые круги дают нулевую delta; перестановка A/B меняет знак; дистанция монотонна; совпадение старта/финиша; корректное пересечение границ секторов; пропуски, шум и дискретные каналы; проверка времени на каждом эталоне.

**Готово, когда:** сравнение воспроизводимо на fixtures; ошибка укладывается в записанные допуски; сомнительные данные помечаются или исключаются; шаг сетки не выдаётся за точность сенсора.

## 9. Этап 4 — внутренний API и выбор кругов

**Цель:** frontend получает готовое сравнение и доступные пользовательские варианты.

Задачи:

- [ ] Вычисления и обращения к источникам выполнять на сервере/worker. При холодном dataset возвращать состояние подготовки с ID задачи и ограниченным polling, не удерживать долгий HTTP-запрос на время всей загрузки.
- [ ] Проверять входные ID, лимит traces, диапазон дистанции/число точек, принадлежность одному уикенду и совместимость конфигурации трассы. Year-to-year и разные трассы отклонять.
- [ ] Вынести детерминированный выбор Best Lap: завершённый, не удалённый, не invalid, без pit-in/pit-out; отдельно учитывать флаги и наличие пригодной телеметрии.
- [ ] Различать официальный лучший валидный круг и лучший круг, пригодный для анализа. Если первый недоступен, объяснять выбор следующего; не подменять его молча.
- [ ] Зафиксировать политику unusual/unknown track status. Не считать неизвестный статус зелёным; при отсутствии подходящего круга показывать причину и доступный ручной выбор.
- [ ] Ручной просмотр разрешает deleted/invalid и pit laps с предупреждением; неполные/несопоставимые круги не обязаны поддерживать полный аналитический compare.
- [ ] Списки сессий строить из данных с поддержкой Sprint Qualifying/Shootout и сегментов квалификации, без фиксированного набора FP1–FP3.
- [ ] Добавить загрузку детализации выбранного диапазона для zoom; публичные ошибки, rate limit, отмену/игнорирование устаревшего ответа при быстрой смене выбора.

**Готово, когда:** API проходит интеграционные тесты на всех основных типах сессий; источник недоступен, но кешированное сравнение открывается; неверный запрос не запускает дорогую загрузку; отсутствие одного канала не ломает ответ.

## 11. Этап 6 — карта трассы и участки преимущества

**Цель:** связать графики с конкретным участком круга.

Задачи:

- [ ] Создать canonical track metadata с версией конфигурации: длина, старт/финиш, сектора, номера поворотов, distanceStart/apexDistance/distanceEnd и происхождение разметки.
- [ ] Переиспользовать проверенные модели трасс. Не строить каноническую карту заново по случайному кругу и не считать визуальное определение поворота готовой спортивной разметкой.
- [ ] Нормализовать координаты сессий к одной геометрии с контролем направления, rotation/scale, старта/финиша и сложных близко расположенных участков трассы.
- [ ] Отобразить старт/финиш, границы секторов и повороты; при выборе поворота переводить все графики в диапазон entry → apex → exit.
- [ ] Связать карту с курсором: при одной distance обе метки показывают одинаковый progress круга. Это сопоставление участков, а не положение машин в один момент гонки; перекрывающиеся маркеры различимы.
- [ ] Разбить трассу на сегменты и считать локальный выигрыш как изменение delta между границами сегмента. Не окрашивать карту по накопленной delta: лидер круга может проигрывать текущий участок.
- [ ] Ввести нейтральный диапазон с учётом качества данных; при hover показывать участок, пилота и выигранное время.
- [ ] Если разметка поворотов отсутствует, сохранять обзорную карту и zoom по дистанции, но не выдумывать номера/границы и corner insights.

**Проверки:** сумма выигрышей сегментов равна изменению delta за круг в пределах допуска; корректное начало/замыкание карты; соответствие sector/corner mapping эталону; синхронность карты и графиков на touch и desktop.

**Готово, когда:** для опубликованного пилотного покрытия доступны карта преимущества и выбор проверенных поворотов; погрешность геометрии не маскируется декоративной плавностью.

## 12. Этап 7 — метрики RaceSide и Insights

**Цель:** дать проверяемые ответы о причинах разницы времени.

Задачи:

- [ ] Описать формулы, единицы, пороги фильтров и правила недоступности каждой метрики; версионировать параметры вместе с вычислениями.
- [ ] Рассчитать top/average speed, full throttle %, braking distance, ранние/поздние точки торможения, gear usage, DRS usage и sector delta.
- [ ] Указать базу процентов: для Full Throttle и usage по умолчанию доля времени на пригодном интервале, а не доля произвольно ресемплированных точек; покрытие интервала показывать в метаданных.
- [ ] Для каждого размеченного поворота считать entry, minimum, maximum и exit speed, braking point, throttle pickup и time delta; отдельно агрегировать straight/corner delta.
- [ ] Значимое торможение определять через сглаживание, порог и минимальную длительность/дистанцию, устойчивость состояния и hysteresis; микросрабатывания не считать отдельными событиями.
- [ ] Разделить начало открытия газа и достижение полного газа после apex/braking phase. Для полного газа требовать устойчивого достижения порога, а не единичного шумового отсчёта.
- [ ] Корректно сопоставлять несколько торможений в одном повороте, отсутствие brake channel, движение без торможения и повторное открытие газа.
- [ ] Создать rule-based Insights: самый значимый участок выигрыша, преимущество на прямой, разница торможения/выхода и газа. Каждый вывод должен ссылаться на вычисленную метрику и участок.
- [ ] Ограничить число выводов, отсекать шум и дубли. Не утверждать причинность, которую телеметрия не доказывает; не делать LLM-вызов для каждого сравнения.
- [ ] Добавить компактный summary и подробную панель поворота; отсутствие достоверной метрики не блокирует остальные каналы.

**Готово, когда:** все минимальные метрики раздела 18 ТЗ реализованы либо обоснованно недоступны на конкретном dataset; braking/throttle tests устойчивы к шуму; значения summary, карты, Insights и финишной delta согласованы.

## 13. Этап 8 — остальные режимы и быстрые сравнения

**Цель:** завершить все пять режимов и сократить путь к полезному сравнению.

Задачи:

**Готово, когда:** все пять режимов доступны на контрольных уикендах; спринт, мокрые сессии и замены пилотов не ломают выбор; ограничения сопоставимости видны пользователю; для простого сравнения не требуется вводить lap number.

## 17. Сквозные технические правила

### Предполагаемые места новых модулей

Это ориентир для небольших локальных добавлений, а не обязательство заранее создать все файлы:

- `src/features/telemetry/` — типы отображения, состояние взаимодействия и компоненты Hub по существующему feature-паттерну LIVE/Replay.
- `src/app/telemetry/` — страницы и metadata.
- `src/app/api/telemetry/` — внутренний публичный API подготовленных данных.
- `worker/telemetry/` — OpenF1Provider, нормализация, derived metrics и задачи подготовки.
- `supabase/migrations/` — минимальные миграции хранения после этапа 1.
- `src/app/api/share-image/telemetry/` — серверные изображения по существующему паттерну.

Детерминированные вычисления должны иметь одну реализацию на сервере; UI и экспорт используют её результаты. Выбор способа обмена типами между TypeScript и `.mjs` уточнить по существующим паттернам, без создания нового монорепозитория.

### Правила данных и точности

- Никогда не сравнивать круги по абсолютному timestamp вместо distance.
- Не переносить геометрию одного года/конфигурации на другую без проверки совместимости.
- Различать официальный timing, интерполированное время и приблизительную оценку; не обещать миллисекундную точность на неподходящем источнике.
- Не объединять deleted, pit и флаговые круги в «плохие» без сохранения причины; validity и аналитическая пригодность — разные признаки.
- Финишная разница, локальный выигрыш на карте и формулировка Insights должны использовать одну знаковую конвенцию.
- Raw history хранится долговременно, но официальные исправления и обновления алгоритмов создают новые версии. «Практически immutable» не означает запрет исправлений.
- Attribution доступен рядом с анализом и в экспорте, если этого требуют условия конкретного dataset.

### Работа по одному этапу

Перед реализацией этапа прочитать актуальные проектные инструкции, этот план и соответствующие разделы ТЗ; проверить изменения рабочей копии. Выполнять этап небольшими локальными изменениями, затем фиксировать результат и подтверждение его критериев готовности. Не отмечать этап завершённым только по наличию файлов.

При работе с frontend применяются `design-taste-frontend` и `impeccable`; для Next.js — `next-best-practices`, shadcn — `shadcn`, продуктовых текстов — `content-design`, Supabase — соответствующие skills, багов — `systematic-debugging`, браузерной проверки — Browser/Playwright. Сам текущий документ не создаёт frontend, миграции или интеграции.

## Аналитика участков — 7 октября 2026

Реализованы три режима в едином верхнем меню сравнения рядом с обычными графиками. «Разбор круга» сохраняет прежнюю аналитику всего круга. Второго меню и переключателя «Весь круг» в верхней панели нет; выбор поворота доступен внутри «Выходов и разгона» и на карте.

- **Сравнение участков:** четыре группы участков, общий ноль на диаграмме преимущества, выбор группы и подсветка карты. Вместо подробных таблиц — главный выигрыш каждого пилота за круг и скорость в выбранной группе. Для поворотов это медиана минимальных скоростей каждого пилота, для прямых — максимальная измеренная скорость. Скорости рассчитаны до сокращения данных для графиков; неизвестные значения не заменяются нулём. Нажатие на ключевой участок открывает соответствующий поворот в «Выходах и разгоне» или ставит курсор на графике скорости полного круга для прямой. Границы общие для обоих пилотов: апексы из существующей разметки, типичные точки торможения и устойчивого полного газа; промежутки между поворотами считаются прямыми. Классы по медиане минимальной скорости двух кругов: ниже 150 км/ч, 150–230 км/ч и от 230 км/ч. Без разметки поворотов этот анализ недоступен.
- **Выходы и разгон:** локальные графики скорости и газа, общий выход за ноль дистанции, раздельное преимущество от апекса до выхода и на следующей прямой. Поперечная полоска на карте перемещается за курсором графика; кнопка «Открыть на графике» убрана. Разницу точек полного газа показываем только за пределами двух отсчётов телеметрии и минимум 25 м. До четырёх независимых пар выбираются отдельно для выхода и следующей прямой: одна сессия, два пилота, реальные круги и непрерывные данные на измеряемом интервале. Жёлтый флаг, удаление круга, погода и известный/неизвестный возраст шин не исключают его автоматически. Приоритет — выбранная пара и ближайшие по времени круги; одинаковый состав шин предпочтителен при равной временной близости. Worker загружает не более восьми дополнительных кругов; их недоступность не ломает основное сравнение. В таблице показаны состав и возраст шин, а вывод содержит число преимуществ из проверенных сравнений и медианную разницу с учётом близкого темпа.
- **Управление энергией:** список и кликабельные интервалы на карте, выбор пилота и типа события, график скорости с выделением интервала и короткие значения газа/тормоза. Отдельные графики педалей, кнопку перехода на график, метку «Эксперимент» и подзаголовок убрали по решению пользователя; в профиле убрали метку «Оценка по телеметрии». «Суперклиппинг» — принятое продуктовое название устойчивого замедления при полном газе и отпущенном тормозе. В `track-analysis-5` газ не ниже 98% в каждом отсчёте, начало эпизода от 300 км/ч, последующие отсчёты от 200 км/ч, падение минимум 8 км/ч за минимум 1 с и 60 м. Тормоз известен и отпущен, передача/DRS стабильны, отсчёты непрерывны с интервалами до 0,5 с. Соседние подтверждённые фрагменты объединяются при паузе до 1,5 с и расстоянии до 150 м, если все промежуточные отсчёты сохраняют полный газ, отпущенный тормоз, передачу/DRS и не показывают восстановление больше 2 км/ч от текущего минимума. Между ними допускаются прямые/быстрые повороты, но не медленные/средние. Повторный разгон разделяет эпизоды также внутри непрерывной серии. Порог начала применяется после объединения: замедление может продолжаться ниже 300 км/ч. Это осторожный порог детектора, не физическая граница рекуперации. Накат: газ до 5%, тормоз отпущен, от 80 км/ч, минимум три отсчёта, 0,5 с и 30 м перед фактическим торможением в пределах 50 м. Ослабление разгона сохраняет прежние условия: газ от 98% на всей исходной серии нажатого газа, интервал от 4 с, начальное ускорение от 3 км/ч/с и конечное от −1 до 1 км/ч/с. Усреднённые круги исключены из поиска событий.

Локальный тайминг считается по полным отсчётам до сокращения данных для графиков. Разрыв больше 0,6 с исключает весь соответствующий участок у обоих пилотов. Сумма категории содержит только совместно доступные участки; рядом показано их число. В профиле сохраняется проверка общего отрыва по секторным границам. В выходах и разгоне проверяются только сектора, пересекающиеся с выбранным интервалом: расхождение больше 0,35 с скрывает его преимущество, а меньшее повышает порог «Близкий темп» (минимум 0,05 с). Для вывода о преимуществе нужны проверки всех пересекаемых секторов; без них доступна только оценка «≈», которая не входит в число преимуществ. Версия анализа входит в ключ сравнения отдельно от версии сырой телеметрии; старые сохранённые сравнения рассчитываются при чтении без записи в базу, используя уже сохранённые нормализованные круги (до 24 записей на пилота с удалением дублей).

Ограничения: границы поворотов приближённые; сравнение характеризует выбранные круги и условия, а не мастерство пилота отдельно от машины. Наблюдаемый суперклиппинг определяется по педалям и скорости; заряд батареи, мегаджоули и электрическая мощность не восстанавливаются, поэтому энергетическая причина не подтверждена. Реальные эпизоды с началом ниже 300 км/ч могут быть пропущены. Ненаблюдаемая пауза не доказывает неизменность педалей; короткий хвост через поворот не дорисовывается без самостоятельного подтверждённого замедления. Возможная энергетическая причина наката или ослабления разгона остаётся гипотезой. Старые сохранённые ссылки не обращаются к внешнему источнику за дополнительными кругами; используют доступный кеш. Соседний круг квалификации может быть кругом охлаждения: измеряем фактическое время участка, не утверждая равенство намерений или условий.

Уточнения 7 октября: «Скорость», «Педали» и «Мотор и передачи» всегда показывают полный круг; поворот из карты и аналитики не меняет их диапазон. В профиле подзаголовок сокращён до «Выигранное время на участках», подробные таблицы заменены компактной сводкой, категории и подсветка карты сохранены. На коротких desktop-экранах сводка располагается в строку, чтобы не требовать прокрутки; диаграмма не сжимается до наложения элементов. Блок повторяемости называется «Повторяемость преимущества». Блок «Как читать этот разбор» убран со всех аналитических экранов по просьбе пользователя. Дополнительное пояснение о пропусках не добавляется.
