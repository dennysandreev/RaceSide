# Проверка скорости RaceSide: 18 октября 2026

## Результат

На production устранены два подтверждённых источника лишней работы: загрузка MTProto SDK при каждом запуске любого worker-задания и потеря обработанных изображений при пересоздании web-контейнера. Полное ускорение всех экранов **не подтверждено**: после выпуска остаются переменные задержки серверного ответа и потоковой выдачи блоков.

Прямая связь обычных страниц с новой моделью болида не подтвердилась. Прямой ответ `/news` не включает chunk Three.js, найденный на главной; основной бинарный ассет болида не предзагружается оболочкой. На главной остаётся прежний глобус. Наличие Three.js на главной само по себе не означает загрузку болида.

## Подтверждённые факты

- На VPS 2 CPU и около 4 ГБ RAM. В нескольких срезах `admin-job-runner` занимал 130–145% CPU. Перезапусков по OOM не обнаружено; во время секундных замеров swap-in/swap-out не происходил. Наличие занятого swap не признано доказательством текущей нехватки памяти.
- Все задания загружали `telegram`, `telegram/sessions/index.js`, `telegram/Utils.js`, включая пустую проверку очереди. Сам импорт worker без запуска задания потреблял секунды CPU.
- В web отсутствовал постоянный том для `.next/cache/images`. Новый контейнер терял ранее обработанные варианты изображений. Прогрев страниц прогревает HTML, а не все изображения.
- Gzip уже работал для реальных GET-ответов JS; отсутствие `Content-Encoding` в HEAD не было принято за отсутствие сжатия.

## Изменения

- MTProto клиент и `StringSession` импортируются только после проверки Telegram-настроек, при создании клиента. `getPeerId` импортируется только для поиска числового Telegram-источника. Проверка авторизации, ограничения повторных соединений и обработка ошибок сохранены.
- В оба Compose-файла добавлен отдельный том `web-image-cache` для web. LIVE spool не менялся. На VPS том называется `app_web-image-cache`.
- Перед реальным пересозданием web в том перенесены 148 файлов кеша, 10 195 731 байт. После пересоздания количество файлов сохранилось; проверочное изображение возвращало `X-Nextjs-Cache: HIT`.
- В существующие ops-проверки добавлен регрессионный тест ленивой загрузки Telegram. Добавлена проверка изоляции image cache от LIVE spool.

Sentry, расписания и интервалы заданий не отключались. Содержимое `.env` и `.env.telegram` проверено по SHA-256 и не изменялось. Фронтенд, модель болида, авторизация, платежная логика и схема базы не менялись. Параллельные локальные правки модели в выпуск не включались.

## Измерения

Старый и новый worker запущены по два раза в отдельных контейнерах на том же VPS, с одинаковыми production env, без сети и без выполнения заданий. Новый образ отличается worker-патчем и его тестом, зависимости сохранены.

| Запуск | До: время / CPU | После: время / CPU |
| --- | ---: | ---: |
| 1 | 7053 / 5707 мс | 2862 / 3318 мс |
| 2 | 6445 / 5356 мс | 3464 / 3335 мс |

Средние расходы CPU на импорт снизились примерно на 40%, среднее время импорта на 53%. **Это не процент ускорения сайта.** Нагрузка остальных заданий, ожидание Supabase, свежесть кешей и холодный запуск web в этот показатель не входят.

Полные HTML-ответы после перезапуска оставались нестабильными: в контрольных внутренних запросах главная занимала 1,5–4,1 с, новости 0,7–5,3 с, календарь 0,35–11,45 с. До выпуска также были скачки до нескольких секунд. Из-за холодного запуска, фоновых задач и различного состояния кешей эти серии не считаются сопоставимым подтверждением ускорения всех страниц. Время полного streamed body не равно времени появления первого видимого блока.

## Проверки

- `node --check worker/index.mjs`, typecheck, lint: успешно. В полном lint остаются 15 прежних предупреждений в vendor-скриптах; в изменённых JS-файлах предупреждений нет.
- Production build прошёл в отдельном снимке без `.env`, с изолированными зависимостями. Первоначальные попытки со ссылкой на внешние `node_modules` не проходили ограничение root Turbopack; после исправления только временного окружения сборка завершилась.
- 45 точечных тестов очереди, расписаний, Telegram, TTL-кеша и уведомлений, 45 billing-тестов и 11 security-тестов прошли. В Linux-образе также прошли 5 новых Telegram-тестов.
- HTTPS smoke: health, главная, новости, календарь, чемпионат, текущий этап, команды, пилоты, Plus: 200. Личный кабинет гостя корректно перенаправляет на вход. Платные LIVE/telemetry API возвращают гостю 401.
- Браузер: лента новостей и команды отображаются; соответственно 22/22 и 23/23 изображений загружены, сломанных изображений не найдено. Это гостевой desktop-сценарий, не измерение iPhone LCP.
- Web и LIVE healthy; cron, admin-job-runner, ops-watcher и cache-warmer работают. После выпуска проверка расписаний и очереди выполнялась; ошибок цикла worker в проверенном интервале не найдено.
